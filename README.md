# food-ai-supplier

Прототип разработан на стеке **Python + Streamlit + LangChain / Mistral AI**.

В качестве концепта (Proof of Concept) архитектура разделена на два изолированных слоя: **слой извлечения данных (Data Extraction)** и **аналитический слой (LLM Reasoning)**.

1. Имитация веб-скрейпинга и локальный датасет

Для обеспечения стабильности веб-деплоя и защиты от блокировок/капч со стороны Cloudflare на облачном хостинге, модуль сбора данных (ранее спроектированный на `Selenium` + `BeautifulSoup`) переведен на работу с подготовленным датасетом сырых, неструктурированных текстовых выгрузок с реальных сайтов поставщиков (категории «упаковка» и «молоко»). Это позволяет продемонстрировать ключевую бизнес-логику ИИ-агента без сетевых задержек.

2. Модуль ИИ-парсинга (Structured Output)

Вместо жестких регулярных выражений или хрупкого парсинга HTML-тегов, сервис использует LLM (**`open-mistral-7b`**). Нейросеть анализирует входящий хаотичный текст веб-страницы и с помощью явного JSON-инструктирования (с Pydantic-валидацией на выходе) структурирует коммерческие условия:

- Название компании
- Минимальный объем заказа / сумма (если указаны)
- Логистические и географические условия доставки
- Прямые контакты (email, телефоны)

3. Аналитический блок сравнения (AI Procurement Agent)

Для выполнения требования ТЗ **«помогать принять решение, с кем лучше связаться»**, реализована функция умного B2B-сравнения. Агент верхнеуровнево сопоставляет извлеченные карточки контрагентов, выступает в роли эксперта по закупкам и генерирует для пользователя персонализированный вердикт-рекомендацию с выделением наиболее выгодных условий.

Масштабирование решения в Production (план развития):

1. **Перенос скрейпинга в фоновый режим (Async Background Workers).** В реальном контуре обход поисковиков (через Serper/Tavily API) и парсинг сайтов через Selenium будут вынесены в асинхронные задачи (например, Celery) по расписанию, чтобы наполнять операционную базу данных (PostgreSQL/SQLite), а не нагружать интерфейс пользователя в реальном времени.
2. **On-Premise контур (безопасность).** В кодовой базе предусмотрена легкая миграция на локальный ИИ-движок (**Ollama / Llama 3.1 / Qwen 2.5**) для обеспечения полной конфиденциальности данных и экономии на токенах внешних провайдеров.

Прототип полностью готов к проверке, интерактивен и демонстрирует продуктовое продуктивное применение LLM-технологий для автоматизации B2B-процессов.
