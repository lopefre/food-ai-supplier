# Сервис поиска и анализа поставщиков питания (AI Procurement Agent)

Прототип разработан на стеке **Python + Streamlit + LangChain / Mistral AI**.

В качестве концепта (**Proof of Concept**) архитектура разделена на два изолированных слоя: **слой извлечения данных (Data Extraction)** и **аналитический слой (LLM Reasoning)**.

1. Имитация веб-скрейпинга и локальный датасет

Для обеспечения стабильности веб-деплоя и защиты от блокировок/капч со стороны Cloudflare на облачном хостинге, модуль сбора данных (ранее спроектированный на `Selenium` + `BeautifulSoup`) переведен на работу с подготовленным датасетом сырых, неструктурированных текстовых выгрузок с реальных сайтов поставщиков (категории «упаковка» и «молоко»). Это позволяет продемонстрировать ключевую бизнес-логику ИИ-агента без сетевых задержек.

2. Модуль ИИ-парсинга (Structured Output)

Вместо жестких регулярных выражений или хрупкого парсинга HTML-тегов, сервис использует LLM (**`open-mistral-7b`**). Нейросеть анализирует входящий хаотичный текст веб-страницы и с помощью явного JSON-инструктирования (с Pydantic-валидацией на выходе) структурирует коммерческие условия:

- Название компании
- Минимальный объем заказа / сумма (если указаны)
- Логистические и географические условия доставки
- Прямые контакты (email, телефоны)

3. Аналитический блок сравнения (AI Procurement Agent)

Для выполнения требования ТЗ **«помогать принять решение, с кем лучше связаться»**, реализована функция умного B2B-сравнения. Агент сопоставляет извлеченные карточки контрагентов, выступает в роли эксперта по закупкам и генерирует для пользователя персонализированный вердикт-рекомендацию с выделением наиболее выгодных условий.

---

## Масштабирование решения в Production (план развития):

1. **Перенос скрейпинга в фоновый режим (Async Background Workers):** В реальном контуре обход поисковиков (через Serper/Tavily API) и парсинг сайтов через Selenium будут вынесены в асинхронные задачи (**Celery / Redis**) по расписанию, чтобы наполнять операционную базу данных (**PostgreSQL / SQLite**), а не нагружать интерфейс пользователя в реальном времени.
2. **On-Premise контур (безопасность):** В кодовой базе предусмотрена легкая миграция на локальный ИИ-движок (**Ollama / Llama 3.1 / Qwen 2.5**) для обеспечения полной конфиденциальности коммерческих данных и экономии на токенах внешних провайдеров.
3. **Переход на полноценную RAG-архитектуру с Vector DB:** Текущий прототип выявил классическую проблему работы с Long Context и dynamic prompt generation на моделях класса 7B — нестабильность синтаксиса разметки (Markdown) и риск пропуска структурных тегов при изменении объема входных данных.

В продакшн-версии система будет переведена на **RAG-паттерн**. Сырые данные будут векторизоваться и храниться в векторной базе данных (**ChromaDB / FAISS**). Под запрос пользователя агент будет извлекать только релевантные чанки (факты), а генеративный слой будет переведен на **Strict Structured Output** (валидация через Pydantic-модели и JSON-mode на уровне API модели). Это полностью исключит поломку интерфейса и обеспечит 100% стабильность формата ответа.
