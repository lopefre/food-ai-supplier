#🥑 Архитектура сервиса поиска и анализа поставщиков питания (Food AI Supplier)

Данный документ содержит техническое описание архитектуры, структуры данных и логики работы прототипа мультиагентной поисково-аналитической системы, развернутой на базе фреймворка **Streamlit**.

1. Назначение и бизнес-логика

Система автоматизирует первичный сбор данных (Data Ingestion) и экспертный аудит контрагентов для департамента снабжения в сфере Food. Сервис принимает на вход текстовый запрос категории товара, имитирует веб-скрейпинг целевых страниц поставщиков и использует LLM-оркестрацию для извлечения изолированных бизнес-констант и генерации финального сравнительного вердикта.

---

2. Спецификация и структура данных (Data Schema)

Для валидации и контроля целостности извлеченных ИИ-моделью данных используется Pydantic-модель `SupplierInfo`.

python

```
class SupplierInfo(BaseModel):
    company_name: str  # Название компании или бренда (обязательное поле)
    min_order: Optional[str] = None  # Минимальный объем/сумма заказа (опционально)
    delivery_terms: Optional[str] = None  # Условия и регионы доставки (опционально)
    contacts: List[str]  # Массив извлеченных контактов (телефон, email, ссылки)
```

Используйте код с осторожностью.

---

3. Компоненты системы и Пайплайн обработки (AI Pipeline)

Система построена по микросервисной логике и разделена на два изолированных ИИ-компонента (двухкомпонентного агента):

Компонент 1. Агент-Экстрактор (`analyze_with_ai`)

- **Роль:** ИИ-ассистент отдела закупок.
- **Технологический стек:** `langchain_mistralai.ChatMistralAI`, модель `open-mistral-7b` (ядро от Mistral AI).
- **Логика работы:** Принимает сырой текст страницы и URL. Через системный промпт принудительно переводит модель в режим генерации валидного `JSON` без использования Markdown-разметки (снижение накладных расходов на токены).
- **Отказоустойчивость:**
    - Перехватывает ошибку десериализации `json.JSONDecodeError` (в случае галлюцинаций модели) и возвращает дефолтную безопасную карточку.
    - Перехватывает сетевые ошибки API и ошибки авторизации (`MISTRAL_API_KEY`), выводя подсказки в Streamlit UI без падения приложения в «белый экран».

Компонент 2. Агент-Аналитик (Сравнительный маркер)

- **Роль:** Эксперт департамента снабжения.
- **Логика работы:** Агрегирует извлеченные Pydantic-карточки всех найденных поставщиков, формирует единый контекст и выполняет комплексный аудит.
- **Защита от галлюцинаций:** Системный промпт содержит жесткое негативное ограничение на использование внешней памяти модели (запрещено выдумывать контрагентов вне предоставленного блока данных).
- **Семантическая разметка (Тегирование):** Модель обязана разметить выходной поток текста тегами `[МЕЛКИЙ_ОПТ]`, `[КРУПНЫЙ_ОПТ]`, `[ЧЕК_ЛИСТ]`, `[ВЕРДИКТ]`.

---

4. Логика интерфейса и Клининг (Streamlit UI & Cleaning)

- **Фронтенд-архитектура:** Динамическая сетка колонок (`st.columns`). Система считывает размерность массива результатов: если контрагент один, интерфейс адаптируется под монолитный контейнер во всю ширину экрана для исключения визуальных пустот.
- **Клининг артефактов (Markdown Linting):** Поскольку LLM склонны дублировать заголовки и ломать вложенность жирного шрифта, на уровне фронтенда внедрен синтаксический очиститель на базе регулярных выражений (`re.sub`). Он удаляет слипшиеся пустые звездочки (`****`, `** **`) и срезает дублирующиеся заголовочные токены перед выводом в `st.tabs` и `st.expander`.
